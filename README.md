# csharp-to-typescript

[![CI](https://github.com/Sarmkadan/csharp-to-typescript/actions/workflows/ci.yml/badge.svg)](https://github.com/Sarmkadan/csharp-to-typescript/actions/workflows/ci.yml)
[![NuGet](https://img.shields.io/nuget/v/CSharpToTypeScript.Generator.svg)](https://www.nuget.org/packages/CSharpToTypeScript.Generator)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Roslyn source generator that converts C# DTOs and enums to TypeScript types at build time.
No runtime reflection, no separate CLI step, no drift between backend contracts and frontend types:
the `.ts` file is regenerated every time the C# project compiles.

## Features

- `[TypeScriptExport]` on classes, records, structs and enums
- Incremental generator (`IIncrementalGenerator`) - negligible build-time cost
- Primitives, nullable types, arrays, `List<T>`, `Dictionary<K,V>`, `Guid`, `DateTime`, tuples
- Nested and referenced DTOs are exported transitively
- Enums as numeric enum, string enum or string union - your choice
- `camelCase` / `snake_case` / unchanged member naming
- `[TypeScriptIgnore]` to drop members
- Deterministic output, safe to commit or to `.gitignore`
- Compile-time diagnostics (`CSTS001` unsupported type, `CSTS002` duplicate name)

## Quick start

```csharp
using CSharpToTypeScript;

[TypeScriptExport]
public record OrderDto(Guid Id, string Customer, OrderStatus Status, List<LineDto> Lines, DateTime? ShippedAt);

[TypeScriptExport]
public record LineDto(string Sku, int Quantity, decimal Price);

[TypeScriptExport]
public enum OrderStatus { Pending, Paid, Shipped }
```

Produces `Generated/types.ts`:

```ts
// <auto-generated by CSharpToTypeScript.Generator />
export interface LineDto {
  sku: string;
  quantity: number;
  price: number;
}

export type OrderStatus = "Pending" | "Paid" | "Shipped";

export interface OrderDto {
  id: string;
  customer: string;
  status: OrderStatus;
  lines: LineDto[];
  shippedAt: string | null;
}
```

## Installation

```bash
dotnet add package CSharpToTypeScript.Generator
```

Optional MSBuild configuration in the consuming `.csproj`:

```xml
<PropertyGroup>
  <CSharpToTypeScript_OutputFile>../frontend/src/api/types.ts</CSharpToTypeScript_OutputFile>
  <CSharpToTypeScript_NamingPolicy>CamelCase</CSharpToTypeScript_NamingPolicy>
  <CSharpToTypeScript_EnumStyle>StringUnion</CSharpToTypeScript_EnumStyle>
  <CSharpToTypeScript_NullableAsOptional>false</CSharpToTypeScript_NullableAsOptional>
</PropertyGroup>
```

## Configuration

Set these as `CSharpToTypeScript_*` properties in the consuming `.csproj`. Every option has a default, so the block above is optional.
Invalid values are reported as `CSTS004` and the default is used.

| MSBuild property | Values | Default | Effect |
| --- | --- | --- | --- |
| `CSharpToTypeScript_OutputFile` | Relative file path | `Generated/types.ts` | Output file, relative to the project directory. Backslashes are converted to `/`. |
| `CSharpToTypeScript_NamingPolicy` | `Unchanged`, `CamelCase`, `SnakeCase` | `CamelCase` | Member names: `FirstName` stays `FirstName`, becomes `firstName`, or becomes `first_name`. |
| `CSharpToTypeScript_EnumStyle` | `NumericEnum`, `StringEnum`, `StringUnion` | `StringUnion` | How enums are emitted. See [Enum styles](#enum-styles). |
| `CSharpToTypeScript_NullableAsOptional` | `true`, `false` | `false` | `false` emits `name: T \| null`. `true` emits an optional member `name?: T`. See [Nullable handling](#nullable-handling). |
| `CSharpToTypeScript_DateAsString` | `true`, `false` | `true` | `true` maps `DateTime`, `DateTimeOffset`, `DateOnly` and `TimeOnly` to `string` (ISO 8601). `false` maps them to `Date`. |

### Type mapping

| C# type | TypeScript |
| --- | --- |
| `string`, `char` | `string` |
| `bool` | `boolean` |
| `sbyte`, `byte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `float`, `double`, `decimal` | `number` |
| `Guid`, `TimeSpan`, `Uri` | `string` |
| `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly` | `string` when `DateAsString` is `true` (default), otherwise `Date` |
| `byte[]` | `string` (base64) |
| `T[]`, `List<T>`, `IEnumerable<T>` (also `IList<T>`, `IReadOnlyList<T>`, `HashSet<T>`) | `T[]` |
| `Dictionary<K,V>` (also `IDictionary`, `IReadOnlyDictionary`) | `Record<K, V>`. The key is `number` for numeric keys and `string` otherwise. |
| `Nullable<T>`, `T?` | `T \| null`, or optional `name?: T` with `NullableAsOptional` |
| Tuples, e.g. `(string, int)` | `[string, number]` |
| `object` | `unknown` |
| `dynamic` | `any` |
| Enums, e.g. `Color` | The enum's name, e.g. `Color` (declared per [Enum styles](#enum-styles)) |

### Enum styles

For `enum Color { Red, Green }`:

`NumericEnum`:

```ts
export enum Color {
  Red = 0,
  Green = 1,
}
```

`StringEnum`:

```ts
export enum Color {
  Red = "Red",
  Green = "Green",
}
```

`StringUnion` (default):

```ts
export type Color = "Red" | "Green";
```

Options can also be set in an analyzer config file instead of the `.csproj`. The generator reads them as global options, so the entry goes in a global section:

```ini
is_global = true
build_property.CSharpToTypeScript_EnumStyle = StringEnum
```

This works when the package's `build/` props are not imported. Those props set every option to its default in the same global config, which conflicts with the `.editorconfig` entry (MSBuild reports `MultipleGlobalAnalyzerKeys`), so the key is dropped and the default applies. With the package installed, set the value in the `.csproj`.

### Nullable handling

For `DateTime? ShippedAt` on `OrderDto`:

`NullableAsOptional` is `false` (default):

```ts
export interface OrderDto {
  shippedAt: string | null;
}
```

`NullableAsOptional` is `true`:

```ts
export interface OrderDto {
  shippedAt?: string;
}
```

With `true`, the `| null` is dropped, so a `null` value from the server is no longer reflected in the type. The `?` only says the property may be absent.

## API overview

| Member | Purpose |
| --- | --- |
| `TypeScriptExportAttribute` | Opt a type in; `Name`, `OutputFile`, `Export` overrides |
| `TypeScriptIgnoreAttribute` | Skip a property or field |
| `GeneratorOptions` | Options model; `FromAnalyzerConfig` reads MSBuild properties |
| `Emit.ITypeMapper` / `DefaultTypeMapper` | C# type symbol to TS type expression |
| `Emit.TypeScriptEmitter` | Renders `interface`, `enum` and whole files |
| `TypeScriptGenerator` | The `IIncrementalGenerator` |

## Attributes

`[TypeScriptExport]` takes three named arguments. `[TypeScriptIgnore]` goes on a property or field.

| Argument | Type | Default | Effect |
| --- | --- | --- | --- |
| `Name` | `string` | The C# type name | TypeScript name of the declaration. |
| `OutputFile` | `string` | `CSharpToTypeScript_OutputFile` | File that receives this type, relative to the project directory. |
| `Export` | `bool` | `true` | `false` omits the `export` keyword. |

The snippets below show only the declarations. Each generated file also starts with the auto-generated banner.

### Rename with `Name`

```csharp
[TypeScriptExport(Name = "Order")]
public class OrderDto
{
    public Guid Id { get; set; }
}
```

```ts
export interface Order {
  id: string;
}
```

### Route to another file with `OutputFile`

```csharp
[TypeScriptExport(OutputFile = "admin/types.ts")]
public class AdminUserDto
{
    public string Login { get; set; } = "";
}
```

Written to `admin/types.ts`, not to the default file:

```ts
export interface AdminUserDto {
  login: string;
}
```

### Drop the `export` keyword with `Export = false`

```csharp
[TypeScriptExport(Export = false)]
public class DraftDto
{
    public string Title { get; set; } = "";
}
```

```ts
interface DraftDto {
  title: string;
}
```

### Drop a property with `[TypeScriptIgnore]`

```csharp
[TypeScriptExport]
public class UserDto
{
    public string Email { get; set; } = "";

    [TypeScriptIgnore]
    public string PasswordHash { get; set; } = "";
}
```

```ts
export interface UserDto {
  email: string;
}
```

### Inheritance

- **Exported base** (any type with `[TypeScriptExport]`, including `Export = false`): the derived declaration uses `extends`, and the base's members are not repeated.
- **Non-exported base**: the base's public members are copied into the derived declaration, base members first.

```csharp
[TypeScriptExport]
public class BaseDto
{
    public Guid Id { get; set; }
}

[TypeScriptExport]
public class OrderDto : BaseDto
{
    public string Customer { get; set; } = "";
}
```

```ts
export interface BaseDto {
  id: string;
}

export interface OrderDto extends BaseDto {
  customer: string;
}
```

```csharp
public class AuditBase
{
    public DateTime CreatedAt { get; set; }
}

[TypeScriptExport]
public class OrderDto : AuditBase
{
    public Guid Id { get; set; }
}
```

```ts
// AuditBase is still emitted as its own declaration, see transitive export below.
export interface AuditBase {
  createdAt: string;
}

export interface OrderDto {
  createdAt: string;
  id: string;
}
```

### Transitive export

Types referenced by an exported type are emitted automatically, with no attribute needed. This covers property types, array and list element types, tuple elements, the underlying type of `Nullable<T>`, and base types.

```csharp
[TypeScriptExport]
public class OrderDto
{
    public Status State { get; set; }
    public List<LineDto> Lines { get; set; } = new();
}

public class LineDto
{
    public string Sku { get; set; } = "";
}

public enum Status { Pending, Paid }
```

```ts
export type Status = "Pending" | "Paid";

export interface LineDto {
  sku: string;
}

export interface OrderDto {
  state: Status;
  lines: LineDto[];
}
```

A transitively reached type goes to the default `OutputFile` (`CSharpToTypeScript_OutputFile`), not to the file of the type that references it. The generator emits no `import` lines. So if an exported type routed to `admin/types.ts` references a type without its own `OutputFile`, the reference cannot be resolved from `admin/types.ts`. Either keep both types in the default file, or give the referenced type its own `[TypeScriptExport(OutputFile = ...)]` pointing at the same file as the referrer.

## Diagnostics

The generator reports these during `dotnet build`. Each diagnostic's help link points to this section.

| Id | Severity | Meaning | Fix |
| --- | --- | --- | --- |
| `CSTS001` | Warning | An exported type uses an unsupported construct. Open generic definitions such as `class Box<T>` are not emitted. | Export a non-generic type instead, or remove `[TypeScriptExport]` from the generic class. |
| `CSTS002` | Error | Two exported types in the same output file resolve to the same TypeScript name. The name is the `Name` argument, or the C# name when `Name` is not set. | Set `Name = "..."` on one of them. The same name in a different `OutputFile` does not conflict. |
| `CSTS003` | Warning | The `.ts` file could not be written, either because the write failed or because the generator threw. The message gives the path and the reason. | Check the path in the message: its directory must be writable, and the file must not be read-only or locked by another program. The content is still in the C# constant `CSharpToTypeScript.Generated.TypeScriptOutput_*` (`Content`). |
| `CSTS004` | Warning | A `CSharpToTypeScript_*` property has a value that cannot be parsed. The default is used, and the message names it. | Use an accepted value. `NamingPolicy`: `Unchanged`, `CamelCase`, `SnakeCase`. `EnumStyle`: `NumericEnum`, `StringEnum`, `StringUnion`. `NullableAsOptional` and `DateAsString`: `true` or `false`. `OutputFile`: a non-blank path without invalid path characters. Enum and boolean values are case-insensitive. |

Pointer types (for example `int*`) are not checked yet. Such a member is written as `p: ;`, which is invalid TypeScript, and no diagnostic is reported. Mark the member with `[TypeScriptIgnore]` until this is fixed.

## How it works

The generator is an `IIncrementalGenerator`. It registers `ForAttributeWithMetadataName` for `CSharpToTypeScript.TypeScriptExportAttribute`, so only annotated declarations enter the pipeline. Their transitive closure is emitted as one TypeScript file per output path. During compilation the content is added in two forms: as a C# constant in the `CSharpToTypeScript.Generated` namespace (`TypeScriptOutput_*`, with `Path` and `Content`), and as the file itself at `$(ProjectDir)/<OutputFile>`. The file is rewritten only when its content changes. Either commit the generated `.ts` file, so contract changes show up in review diffs, or add it to `.gitignore` if the frontend build always regenerates it.
